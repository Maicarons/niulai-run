## 1. 源精灵图处理方案（切片）

### 1.1 实测事实（可靠，来自程序化分析）

| 项 | 值 |
|---|---|
| 文件 | `public/assets/sprites/niulai.png`（已就位，由主理人复制） |
| 尺寸 | 273 × 252 px |
| 格式 | PNG / RGBA（带透明通道） |
| 横向 | **无贯穿透明列**；帧横向紧密排列，列间距约 2–4px 缝隙 |
| 纵向 | **6 个内容块**，每块高 38px，块间 3–5px 透明间隔（gutter） |
| 列间距（pitch） | 21 px（273 ÷ 13 = 21，整除） |
| 行间距（pitch） | ≈ 42 px（38 内容 + ~4 间隔） |
| 每行动画帧数（实测） | 行0=12，行1=12，行2=11，行3=11，行4=9，行5=6 |
| 可见总帧数 | ≈ 61 帧 |

> ⚠️ **对最初「13列×12行、21×21」假设的修正**：逐行透明像素分析显示纵向只有 **6 个内容块**（间隔出现在 y≈42/85/127/168/210，而非每 21px 一处），因此这是 **6 行动画条 × 最多 13 列、单元约 21×42** 的布局，**不是 12 行 21×21**。请以本实测为准。

### 1.2 推荐切片方式

**方式 A（推荐，固定网格，便于 PixiJS `AnimatedSprite`）**

- 以原点 (0,0) 起，按 **单元 21（宽）× 42（高）** 切出 13 列 × 6 行 = 78 个格子。
- 逐行丢弃「整格全透明」的尾部空帧，得到真实帧序列：行0=12、行1=12、行2=11、行3=11、行4=9、行5=6。
- 渲染时 `texture` 以 `frame = Rectangle(21*col, 42*row, 21, 42)` 取用，关掉 `imageSmoothingEnabled`。

**方式 B（备选，按缝隙自动检测）**

- 对每行检测全透明列缝隙（已测得各行的空列 run），按缝隙切出精确帧边界，可得到非整数对齐的 tighter 帧（内容约 15–18px 宽）。

> 工程实现统一采用 **方式 A**（固定 pitch），由程基岩在 PixiJS 中按 `frame` 矩形取帧；如需更紧裁切再用方式 B 重导。

### 1.3 帧尺寸 / 帧数 / 每行动画含义（推断）

| 行 | 实测帧数 | 推断动画 | 置信度 | 说明 |
|---|---|---|---|---|
| 0 | 12 | idle（待机/呼吸/张望） | 中 | 帧数最多，通常为循环待机 |
| 1 | 12 | run（奔跑） | 中 | 同为 12 帧，常是主移动循环 |
| 2 | 11 | jump（起跳/上升） | 低 | 需截图确认，可能是第二段跑或跳跃 |
| 3 | 11 | fall（下落/坠落） | 低 | 可能与 jump 组成起降对 |
| 4 | 9 | hurt（受伤/击退） | 低 | 帧数偏少，疑似受击 |
| 5 | 6 | win（胜利/庆祝） | 低 | 帧数最少，疑似一次性庆祝 |

> 🔴 **待切片工具确认**：上述「行→动画」的语义映射为**推断**，因当前环境无法肉眼查看像素。请用 Aseprite / TexturePacker / 自写预览脚本导出每帧并人工标注后，回填确切映射与每帧锚点。

## 2. 角色像素归并（源图→干净像素）

源图实测主色为金色 `#E8B30F` 系，但同一金色存在 **10+ 个近似抗锯齿色**（如 `#E8B30F`/`#E9B410`/`#F4C63F`/`#EBB610`…），描边为 `#2F1300`。为符合 art-bible §3 的「3 档明度」要求：

1. 将全部金色近似色归并到 3 档：**亮 `#F4C63F` / 中 `#E8B30F` / 暗 `#C98A0A`**。
2. 描边统一为 `#2F1300`（1px）。
3. 导出为 **索引色（indexed, ≤16 色）PNG**，去除抗锯齿。
4. 输出两份：原始 `niulai.png`（占位/调试）与重制 `niulai_clean.png`（正式）。

## 3. 推荐动画状态列表

游戏逻辑需要的状态（部分源图已含，部分需补充）：

| 状态 | 源图 | 处理建议 |
|---|---|---|
| idle | 行0（推断） | 直接用，循环 |
| run | 行1（推断） | 直接用，循环；速度映射帧率 |
| jump | 行2（推断） | 直接用，起跳→上升 |
| fall | 行3（推断） | 直接用，与 jump 衔接 |
| hurt | 行4（推断） | 直接用，受击一次性 |
| win | 行5（推断） | 直接用，过关/胜利一次性 |
| slide（滑铲） | **源图无** | 占位阶段用 run 帧 + 水平压扁（squash）；正式需补 2–4 帧 |
| dash（冲刺） | **源图无** | 占位阶段用 run 帧 + 代码残影/速度线；正式需补帧或纯特效 |

> 确认 slide/dash 是否需要独立帧，由文策渊在 GDD 玩法章节定稿后回填（需美术补充则列入 Phase 2 资产清单）。

## 4. 场景素材需求清单

| 类别 | 资产 | 规格建议 | 来源建议 |

## 5. Kenney 等免费像素素材推荐

| 搜索关键词（Kenney 官网 / itch / OpenGameArt） | 用途 | 许可 | 使用建议 |
|---|---|---|---|
| `kenney pixel platformer` | 角色/瓦片/障碍基础包 | CC0 | 风格扁平、限色，匹配度高；按需重染到本项目调色板 |
| `kenney 1 bit pack` | 极简像素元素（可重染） | CC0 | 适合做 UI/图标底，统一描边 |
| `kenney animal pack` / `kenney tiny characters` | 备用动物角色参考 | CC0 | 仅作「牛角/牛鼻」加工参考，**不直接替代牛来** |
| `kenney nature pack` / `kenney foliage` | 草、树、云、山 | CC0 | 背景与装饰层主力来源 |
| `kenney ui pack` / `kenney game icons` | 按钮、心、币、暂停 | CC0 | UI 图标直接复用或重染 |
| `kenney tilemap` / `kenney road` | 地块拼接 | CC0 | 地面/平台瓦片 |

**使用原则**
1. 仅采用 **CC0 / 公共领域** 素材，保留作者署名（Kenney 要求署名或捐赠，按条款执行）。
2. 所有外部素材导入后**必须重染到本项目调色板**（art-bible §2）并归并到 3 档明度，禁止原色直接混入。
3. 与 `niulai.png` 风格对齐：扁平、1px 描边、最近邻缩放。
