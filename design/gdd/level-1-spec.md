# 《牛来》L1 草甸起跑 — 数值规格 (Level 1 Spec)

> 版本：v0.1 ｜ 作者：文策渊 (design-strategist)
> 关联：level-design.md（L1 草案）、core-loop.md、ui-flow.md、docs/architecture/adr-002-rendering.md
> 用途：**工程垂直切片（cheng-jiyan）直接输入**。坐标系：X 向右、Y 向下；原点为关卡左上角。

## 0. 概览
- 关卡名：草甸起跑（L1）；主题阳光草甸，教学友好。
- 本关只教「自动跑 + 跳」。引入 **O1 地刺**、**O3 深坑**；**O2 低悬留到 L2**（故本关不使用 slide）。
- 节奏：暖身 → 首秀(单刺) → 巩固(双刺) → 引入间隙(坑) → 综合考核(双刺+坑) → 分支(高/低路线) → 终点。
- 星级：★ 完赛 / ★★ 全收集(15 币) / ★★★ 全收集 + 无伤。

| P2 | O3 深坑 | 1350(中) | [1320, 1380] | 综合 | 宽 60，接在 S5 后 |

**节奏可过性验证（按 §5 物理，V_run=240, V_jump=700）：**
- 跳跃水平距 ≈168px ≫ 坑宽 80/60 → 留足跨越余量（首跳即过，教学友好）。
- 双刺间距 120px < 跳跃水平距 → 一次定时跳可双清，或分两段跳，均无强制连跳压力（巩固段宽松）。
- 综合段 S5(1120) → P2(1320)：落点约 1168 后，距坑 152px（≈0.63s 反应）→ 节奏提速但仍可反应。
- 所有间距/坑宽均按「可反应窗口」留余量；精确手感以 §5 标注值联调。

## 5. 角色数值建议（供程基岩先用，标注「待手感联调」）
| 参数 | 建议值 | 单位 | 说明 / 待联调 |
|------|--------|------|----------------|
| `V_run`（跑速） | 240 | px/s | 自动向右；**待手感** |
| `G`（重力） | 2000 | px/s² | 固定步长 60Hz 积分；**待手感** |
| `V_jump`（起跳速度） | 700 | px/s（向上） | **待手感** |
| 跳高 apex（派生） | ≈122 | px | = V_jump²/(2G) |
| 跳跃水平距（派生） | ≈168 | px | = V_run × 滞空(0.7s)，须 > 坑宽 |
| `T_slide`（滑铲时长） | 0.5 | s | 本关不用(O2 在 L2)；滑时碰撞高→28 |
| `C_dash`（冲刺冷却） | 1.5 | s | 本关不用；冲刺时长 0.25s，爆发 ≈+150px |
| `MAX_HP` | 3 | — | 已定；撞/坠 −1，hp=0 失败 |
| `I_FRAME`（受击无敌） | 1.0 | s | 受击后短暂无敌，防同障碍连扣 |
| 碰撞盒（站立） | 32 × 56 | px | 宽 × 高 |
| 碰撞盒（滑铲） | 32 × 28 | px | 高度减半 |

**受击/坠落处理**：撞地刺 → −1 HP + 播 hurt(行4) + I_FRAME 1s，不中断自动跑（继续）；坠坑(脚底>DEATH_Y) → −1 HP + 在「最后安全落地点」重生（速度归零），**非关首重开**（保 P4 心流）。hp=0 → `level:failed{reason:"hp=0"}`。

## 6. 动画状态 → 源图行映射（供切片）
源图 `niulai.png`（路径 `public/assets/sprites/niulai.png`，见 asset-spec.md §1）：273 × 252 px。按 team-lead 指定 **6 行动画**，权威映射见 §6 与 asset-spec.md §1.4：

| 状态 | 行索引 row | 行 y 区间（行高 42） | 触发 |
|------|-----------|----------------------|------|
| idle | 0 | [0, 42) | 待机（出生/暂停） |
| run | 1 | [42, 84) | 奔跑（默认） |
| jump | 2 | [84, 126) | 起跳上升 |
| fall | 3 | [126, 168) | 过 apex 下落 |
| hurt | 4 | [168, 210) | 受击（−1 HP 瞬间） |
| win | 5 | [210, 252] | 抵达终点 |

切片参数：渲染枚举行索引 0–5（与 asset-spec §1.4 行→动画映射一致）；行高 ≈ 42 px（含 gutter），6 行。各行动帧数取自 asset-spec §1.2 **方式 B（逐行列缝隙检测边界）**的权威值（非空透明列段即一帧，动态统计）：**idle=12 / run=12 / jump=12 / fall=11 / hurt=9 / win=7**。> 注意：**帧宽不统一、非固定 21px**，按逐行列缝隙检测、动态统计，待切片预览肉眼确认，允许 **±1 帧**误差；固定 21×42 网格（asset-spec §1.4 方式 A）仅作粗略占位，给出全 13 列（非真实帧数）；早期一次缝隙检测曾误计 jump=11 / win=6，已作废（见 asset-spec §1.1 校正记录），现以 方式 B 为准。
状态机：`run ↔ (jump→fall→run)`；**`land` 非独立渲染态**——落地如无特殊帧即复用 fall 末帧或立即回 `run`（不列入 6 态枚举）；受击切 `hurt`（I_FRAME 内）后回 `run`；终点切 `win`。**slide / dash 非渲染态**（见 §8）：渲染上 slide 复用 run 帧（行 1）+ 代码 squash（高度压扁），dash 复用 run 帧（行 1）+ 代码残影；二者仅为逻辑动词，无专属源图行。

## 8. 依赖与一致性
- **动画枚举一致性（已收尾，T2.3）**：本规格采用的渲染枚举 `AnimationState = {idle=0, run=1, jump=2, fall=3, hurt=4, win=5}`（6 态）为权威映射，见本 §6 与 asset-spec.md §1.4。concept / core-loop / level-design 已同步：slide / dash 明确为**逻辑动词**（复用 run 帧 + squash / 残影），不列入渲染枚举；`land` 非独立态（落地复用 fall 末帧或立即回 run）。三文档动画引用现已一致，无需 Phase 2 二次回填；亦闭合 asset-spec §1.5 的「slide/dash 是否补独立帧」待定项（MVP 结论：不补，复用 run 帧）。
- **帧宽 / 每行动帧数**：待 **lin-wayson（art-director）** 确认（影响 §6 精确切片；当前只需行索引）。
- **物理数值**：§5 全部标「待手感联调」，建议程基岩先按默认值跑通垂直切片，再在玩法 Phase 调参。
- **红线自检**：同屏决策点 ≤1（L1 仅跳）；地刺红 / 坑深色高对比；扣血制 hp=0 才失败，避免 P4 心流断裂；金币仅评星不影响通关（无 P2W）。
